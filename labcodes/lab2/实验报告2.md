## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本实验让内核能够知道有哪些物理内存、哪些内存已被占用、剩余内存如何分配，并理解地址翻译与内存分配之间的关系。

启动汇编先准备页表并开启 Sv39，跳入高地址的 `kern_init()`。C 入口清零 BSS，调用 `dtb_init()` 解析固件传入的设备树，得到内存基址和长度。随后 `pmm_init()` 选择分配器，调用 `page_init()` 建立描述符和空闲区，并执行分配器检查。

```text
OpenSBI 传入 a0/a1
  → entry.S 保存 hartid/DTB，设置 satp，跳入高地址
  → kern_init：清零 BSS、解析 DTB
  → pmm_init
      → init_pmm_manager：初始化管理器状态
      → page_init：描述物理页并排除已用区域
          → init_memmap：向管理器登记空闲页
      → alloc_pages/free_pages 与检查
  → 在页分配之上提供 kmalloc/kfree
```
### 2.2 功能的逐步实现

1. 首先实现**物理内存初始化**：解析设备树提供的内存范围，建立 `Page` 数组并保留固件、内核和元数据所占页面，为分配器提供合法空闲区。
2. 接着理解 **First-Fit 并实现 Best-Fit**：在相同页管理接口下完成连续页分配、拆分、释放和相邻合并，建立后续扩展的基线。
3. 然后实现 **Buddy System 并独立设计测试**：按二次幂组织页面，验证拆分、真正伙伴合并和不规则初始区间，明确其取整分配契约。
4. 在稳定的页分配之上实现**简化 SLUB 及其测试**：将整页划分为不同大小的对象，并验证对象数据、复用和整页回收。
5. 最后结合 **QEMU、评分脚本与客体 GDB** 验证整体行为，分析页表转换过程。实际验证中先后修复固件启动入口和分页切换映射问题，之后才得到完整自测输出。

### 功能模块一：物理内存初始化功能

**负责人：** 2411147-张永昌。

#### 模块功能描述

**需要实现/修改的函数：**

```c
static void page_init(void);
static void init_pmm_manager(void);  // 接入默认页分配器
```

**功能说明：**

`page_init()` 从 DTB 接口读取内存信息，设置 `va_pa_offset`，验证起点、长度及加法溢出。现有 `page2ppn()` 使用固定 `nbase`，因此本实现只接受框架规定的 `DRAM_BASE`，不假装支持任意硬件基址。

管理上界为 DTB 末端与 `PHYSICAL_MEMORY_END` 的较小值，并向下按页对齐。大于 128MiB 的 RAM 只管理当前框架允许的部分。`npage` 是物理页号上界，描述符数量是 `npage - nbase`。

`pages` 是 `end` 后按页对齐的虚拟地址。在写描述符之前先验证数组完整落在可管理内存中，防止元数据初始化本身越界。每个描述符先设置保留、零引用、零长度，并初始化链表节点。

布局为：

```text
OpenSBI | 内核镜像 | 对齐 | Page 数组 | 对齐 | 可分配完整页 | 不足一页的尾部
```

数组物理末端向上对齐后，若仍小于管理上界，调用 `init_memmap(pa2page(free_begin), count)`。空区间不调用。内存不足以容纳内核或描述符数组时 panic，因为系统无法建立合法的管理结构。

##### 地址与描述符的区别

- 虚拟地址：CPU 在分页模式下使用的地址，例如 `end` 和 `pages`。
- 物理地址：RAM 中的位置，可由 `PADDR()` 或 `page2pa()` 得到。
- 物理页号：物理地址右移 `PGSHIFT`。
- `Page *`：描述页状态的元数据地址，不是被描述页面的数据地址。

只有描述符数组之后的完整页面进入分配器；OpenSBI、内核及数组占用的页保持 reserved。设备树已在早期解析，遵循本实验框架允许回收原始 DTB 存储区的约定，不是通用系统保留区解析器。

### 练习：理解 First-Fit 连续物理内存分配算法

**负责人：** 2411156-宋伯宸。

`default_init()` 初始化空闲链表和空闲页总数；`default_init_memmap()` 将指定 reserved 页转为可用页，用块头的 `property` 保存连续页数，并按地址加入链表。

`default_alloc_pages(n)` 从链表开头查找第一个长度至少为 n 的块。若长度正好相等，移出整块；若更大，把前 n 页交给调用者，剩余部分成为新的空闲块。更新计数，清除已分配块头的空闲标记。

`default_free_pages()` 重置释放页的状态，将块按地址插回，然后检查前后邻居。如果前块末端等于本块起点，就与前块合并；随后检查与后块的相邻性。比较的是物理页连续关系，而不是链表节点仅仅相邻。

**改进空间：**当前链表查找是 O(F)，F 为碎片块数。可以增加大小索引或分级空闲链表，减少查找；也可以采用 Next-Fit 减少重复扫描，但它改变选择策略，并不保证碎片更少。批量分配释放、合适的元数据设计和并发保护也可改善实际使用。优化需要权衡内存开销、维护复杂度和碎片，不能宣称某种策略在所有负载上更优。

**负责人：** 2411156-宋伯宸。

#### 模块功能描述

```c
// 定义 const struct pmm_manager best_fit_pmm_manager；

```

**功能说明：**

空闲块仍按地址排序，以便合并；分配时遍历所有足够大的块，选择最小者，同大小时保持先遇到的低地址块，遇到精确匹配可以提前结束。拆分、释放、相邻合并和计数沿用框架约定。

定义完整 `best_fit_pmm_manager`，注册初始化、登记、分配、释放、查询和检查函数。在 `init_pmm_manager()` 中默认选择该管理器。`basic_check()` 和 `best_fit_check()` 与原压缩包内容一致。

分配选择耗时 O(F)，释放查找插入位置也是 O(F)，描述符外只使用常数级管理状态。

##### 改进空间

可以增加按块大小组织的平衡树，利用 lower_bound 找最小可用块，同时保留地址索引用于相邻合并。这样能降低搜索复杂度，但增加元数据和同步维护开销。

Best-Fit 每次剩余空间最小，并不等于长期碎片最少；小余块可能难以复用。可以根据负载采用大小类别或小块拆分阈值，但若多分配了页，必须同时修改接口契约并记录实际长度，不能直接套到要求精确页数的现有测试中。

### 练习：Buddy System（伙伴系统）分配算法

**负责人：** 2411156-宋伯宸

#### 模块功能描述

**需要实现/修改的函数：**

```c
static size_t block_size(unsigned order);
static void buddy_init(void);
static void put_block(struct Page *p, unsigned order);
static void buddy_init_memmap(struct Page *base, size_t n);
static struct Page *buddy_alloc_pages(size_t n);
static void buddy_free_pages(struct Page *base, size_t n);
static size_t buddy_nr_free_pages(void);
static void check_lists(void);
static void buddy_check(void);
// 定义 const struct pmm_manager buddy_pmm_manager；
// 在 pmm_init(void) 中接入验证与管理器切换。
```

**功能说明：**

使用 0 到 18 阶空闲链表，k 阶块含 `2^k` 页。`init_memmap()` 将任意起点、任意长度的初始区间拆成按绝对物理页号对齐的二次幂块，不要求整个空闲区大小恰好为二次幂。

请求 n 页向上取整到某阶，从该阶或更高阶取块，逐级拆分；块头记录实际页数与分配头标记。伙伴物理页号通过 `PPN XOR block_pages` 得到；只有它也空闲且大小相等才合并，反复向高阶推进。

空闲页总数按实际占用扣除。例如申请 3 页占用 4 页，申请 5 页占用 8 页。释放时可传原请求页数，按相同取整规则验证实际块大小。本接口不支持将一个 Buddy 分配随意拆开分批释放；不能把 Best-Fit 的释放契约无条件套用到伙伴分配器。

分配与合并按阶进行，复杂度为 O(MAX_ORDER)，初始化与 Page 描述符数量有关。这里只处理单核启动时使用，不提供并发保证。

##### 测试覆盖与有效性

| 测试 | 检验的错误 |
|---|---|
| 1、3、5 页请求与计数 | 向上取整错误、按请求而非实际占用扣数 |
| 比较分配区间不重叠 | 同一块重复分配、拆分后元数据错误 |
| 超大请求失败且计数不变 | 越界阶、失败路径破坏状态 |
| 检查各阶块长度和 PPN 对齐 | 错阶插入、错误的对齐基准 |
| 64 页隔离场中只登记偏移 1 的 31 页 | 不规则范围拆分和边界处理 |
| 相邻但非伙伴的两页不能满足 2 页请求 | 把相邻关系误当伙伴关系 |
| 分配全部 31 个单页再回收 | 耗尽处理、重复分配、逐级合并 |
| 回收后获得正确的 16 页块 | 不只恢复计数，还真正恢复可合并块 |

### 练习：任意大小内存单元的简化 SLUB 分配算法

**负责人：** 2411156-宋伯宸

#### 模块功能描述

**需要实现/修改的函数：**

```c
static void init_caches(void);
static unsigned cache_index(size_t size);
static struct slab *new_slab(size_t npages, size_t unit);
void *kmalloc(size_t size);
void kfree(void *ptr);
static void verify_bytes(void *ptr, size_t n, unsigned char value);
void slub_check(void);
```

**功能说明：**

底层通过当前页管理器申请物理页。上层设置 16、32、64、128、256、512、1024、2048 字节八类缓存。

一个小对象 slab 占一页，页首保存 magic、链表、空闲对象指针、对象大小、使用数量、容量和原始申请页数；对象区从 16 字节对齐的位置开始，空闲对象自身存储 next 指针。

partial 链表只保留还有空闲对象的 slab。满 slab 移出链表；释放使满 slab 重新有空位时加回；最后一个对象释放后立即把页还给底层。因此测试完成后没有缓存页遗留，之后才能安全切换页管理器。

大于 2048 字节的请求走连续页分配，数据区位于头部之后，记录原始请求页数。Buddy 可能实际多分配页面，但 kfree 使用原始页数，按其接口正确释放。0 和明显超出框架上限的请求返回 NULL，`kfree(NULL)` 无操作。

本实现体现了 SLUB 的缓存与对象管理思想，不等同于 Linux 完整实现：没有 per-CPU 缓存、NUMA、锁及调试设施。释放函数为识别活跃 slab 中的重复释放会扫描空闲对象链表，因此没有声称所有操作严格 O(1)。调用方必须只释放合法对象起点且只释放一次；不能保证对任意野指针安全返回。

##### 测试覆盖与有效性

在 Buddy、Best-Fit 下分别执行相同测试：覆盖各类大小边界、2048/2049 分流边界、页容量边界、4096 和 8193 字节的大对象，确认至少 16 字节对齐。

先同时分配不同大小对象，写入不同模式，逆序验证每个请求字节并释放；重叠或提前回收将导致模式校验失败。再分配 320 个 32 字节对象迫使跨越多个 slab，交错释放一半、重新分配、验证全部对象，检查复用没有破坏仍存活的数据。

测试还覆盖零大小、最大整数请求和 NULL 释放。最终检查底层空闲页数恢复以及 partial 链表为空，检验页回收和缓存状态。当前没有主动注入物理内存耗尽来测试 SLUB 分配失败；已有失败参数测试不等于覆盖所有 OOM 情况。

### 练习：GDB 调试页表查询过程

**负责人：** 2411156-宋伯宸、241114-张永昌。

##### 实测证据与范围

执行 `python3 tools/capture_mmu.py`，原始输出见 [mmu-gdb.log](lab2/lab2_new/verification/mmu-gdb.log)。

记录到：

```text
分页前 PC=0x80200000，satp=0
分页后 PC=0xffffffffc02000d6，satp=0x8000000000080206
根页表 VA=0xffffffffc0206000，PA=0x80206000
根项 [2] 和 [511] 均为 0x200000cf
```

本次实际单步的指令为 `sd ra,8(sp)`，指令地址 `0xffffffffc02000ec`，计算得到有效虚拟地址 `0xffffffffc0205ff8`，物理地址 `0x80205ff8`。执行后，通过恒等映射别名读取这 8 字节，验证与执行前的 ra 值 `0x8000ae9a` 一致。ra 来自本次固件运行，不应在其他环境硬编码。

##### 地址翻译关键流程

Sv39 地址分为 VPN[2]、VPN[1]、VPN[0] 和 12 位页内偏移。satp 的 MODE 为 8，PPN 左移 12 得根表地址。每级用索引乘 8 定位页表项；非叶项指向下一张表，叶项产生映射，并检查有效位、权限、对齐及访问类型。

本项目根项已经是 1GiB 大页叶项：`0x200000cf` 的 V/R/W/X/A/D 为 1，PPN 对应 `0x80000000`。本次 VPN[2]=511，在根层就结束，不会继续访问两张下级表。大页下低 30 位来自虚拟地址：

```text
PA = 0x80000000 | (VA & 0x3fffffff)
0xffffffffc0205ff8 → 0x80205ff8
```

不能使用只适合 4KiB 叶项的“PPN 加低 12 位”公式解释这次大页访问。

##### QEMU 4.1.1 源码路径和关键分支

以下是源码分析，非宿主机断点回溯。数据访问慢路径在 `accel/tcg/cputlb.c` 的 load/store helper 中检查软件 TLB；未命中时还检查 victim TLB，再调用 `tlb_fill`。取指有独立路径，不能把同一套函数名机械套到所有访问。[QEMU 4.1.1 cputlb.c](https://github.com/qemu/qemu/blob/v4.1.1/accel/tcg/cputlb.c)

RISC-V 回调 `riscv_cpu_tlb_fill()` 调用 `get_physical_address()`，后者根据特权状态与 satp 决定直通或遍历页表。成功后检查访问许可并经 `tlb_set_page()` 填表；失败则进入异常路径。遍历中的关键分支是非法项、下一层指针、叶项、权限失败和大页未对齐。[QEMU 4.1.1 cpu_helper.c](https://github.com/qemu/qemu/blob/v4.1.1/target/riscv/cpu_helper.c)

宿主机为 x86 时，`tcg_out_qemu_ld/st()` 使用 `tcg_out_tlb_load()` 生成 TLB 检查代码；命中后的快速访问可能直接在动态生成的机器码中执行。所以只在 C 慢路径设断点，不能证明每次访问都经过该函数。[QEMU 4.1.1 x86 TCG 后端](https://github.com/qemu/qemu/blob/v4.1.1/tcg/i386/tcg-target.inc.c)

##### 能否找到 TLB 查询的 C 代码

能找到用于查询、维护或生成查询代码的 C 实现，例如上述 `load_helper()`、`tlb_hit()` 调用处以及 TCG 生成函数。应区分“生成访存机器码的 C 函数”和“访存时实际执行的代码”。源码位置已核对；宿主机 GDB 中的命中/未命中现场仍需按 [调试补充.md](lab2/lab2_new/调试补充.md) 演示，不能把源码分析当作已执行的调试。

##### QEMU TLB 和真实 CPU TLB 的逻辑区别

真实处理器的 TLB 服务硬件地址翻译；其容量、关联度、替换策略受具体微架构影响。QEMU 的软件 TLB 为模拟器加速，除客体地址信息还涉及宿主机地址偏移和 RAM/MMIO 处理；不能用它推断真实 CPU 的周期数或缓存组织。

未开启分页时，客体地址可按相应特权规则直通为物理地址，但模拟器仍需找到宿主机中对应的 RAM 或设备，因此软件 TLB 机制仍有意义；不能把“客体不查页表”误解成“模拟器不使用任何地址缓存”。这些判断与上述源码中的 Bare/特权直通分支及通用 TLB 机制相符。

##### 有趣细节和 AI 解决的问题

最直观的现象是新增分配器代码能正常编译，但系统完全不打印 DTB 信息。开始的问题位于固件跳转，修复后又暴露分页后的取指异常。第二次异常恰好发生在 `csrw satp` 后的 `0x80200038`。通过 QEMU 异常日志与反汇编定位，而不是反复修改分配器。

这里说明“地址翻译”影响取指，不只影响显式 load/store；开启分页和跳高地址之间也需要合法映射。另一个细节是“大页让三级结构只读一个根项”，层数上限不等于实际访问层数。

AI 协作记录保留了从报错现象、提出假设、查看日志/源码到修复并复测的过程。我们没有凭预期补造测试通过或宿主机源码调试经历。

## 六、实验总结与收获

### 对操作系统的理解

1. **本实验的重要知识点及其与 OS 原理的关系、差异**

| 实验中的知识点 | 对应 OS 原理及关系、差异 |
|---|---|
| DTB、Page 数组、reserved | 对应物理内存发现和资源记账；实验只支持框架的单段 DRAM，通用 OS 还处理多段与保留区 |
| First-Fit/Best-Fit | 对应连续分配与外部碎片；具体链表和 property 是本实验的实现方式 |
| Buddy | 对应二次幂分配、快速拆合；减轻外部碎片问题但引入取整内部碎片 |
| SLUB 对象缓存 | 对应内核小对象分配；把页分配与对象分配分层，简化版不具备完整 Linux 特性 |
| satp、PTE、大页与 TLB | 对应虚拟地址翻译和局部性；静态 1GiB 映射与完整进程地址空间管理仍有距离 |
| 描述符与空闲计数 | 对应元数据开销和不变量；分配器必须管理自身所需空间 |

2. **OS 原理中重要、但本实验未对应实现的知识点**

按需分页、页面置换、缺页处理、交换空间、进程独立页表、写时复制、共享内存，以及多核 TLB shootdown、NUMA 和并发分配。
